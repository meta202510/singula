# singula — 小説批評ツール（Excel VBA / Python）

Windows版ExcelのVBAからOpenAI APIを呼び出し、小説の批評をテキストに出力します。Pythonや追加のVBAライブラリは不要です。Windowsデスクトップ版Excel向けで、Mac版・Web版Excelには対応していません。

独立して使えるPython版もあります。Python版はExcelを必要とせず、Windows・macOS・Linuxのコマンドラインで実行できます。以下の「Python版」を参照してください。

ローカルで使えるデスクトップ画面も追加しました。「Python版の画面」を参照してください。

## 評価の流れ

入力テキストは次の形式に対応します（Python版・Excel版共通）。

```text
【タイトル】
『作品名』

【本文】
小説の本文……
```

5人の審査員はタイトルを認識し、その意味や本文との関係を踏まえて読みます。批評文にタイトルを必ず書かせる指定はしていません。見出しのない従来の入力も使用できます。タイトル・見出し・本文を含む入力全体を各審査員に渡し、文字数の閾値も入力全体に適用します。総評には引き続き5人の批評だけを渡します。モックの固定文は実際の作品の内容を評価しません。

1. 小説の `.txt` ファイルを選択する。
2. 5人の審査員が、それぞれ小説全文だけを受け取って批評する。
3. 6人目が、5人の批評だけを受け取って総評を書く。
4. 元のファイル名、審査員１～５の批評、総評の順で、UTF-8（BOM付き）の `.txt` ファイルに保存する。

5人のリクエスト間で会話履歴・他人の批評は共有しません。全員が同じ評価方針で独立に読みます。同じモデルによる評価であり、意見が必ず異なることを保証するものではありません。APIは順番に6回呼び出します。

## Excel版の導入

1. `dist/singula-excel.zip` を展開する。ZIP内の `.bas` は日本語版WindowsのVBE向けにCP932で保存しています。リポジトリの `excel/` 内は開発用UTF-8です。
2. Excelで空のブックを作り、**Excelマクロ有効ブック（.xlsm）** として保存する。
3. `Alt + F11` でVBEを開き、「ファイル → ファイルのインポート」から、展開した `Json.bas`、`NovelCritique.bas`、`MockReview.bas`、`CritiqueTests.bas` の4つを取り込む。
4. VBEで「デバッグ → VBAProjectのコンパイル」を実行する。
5. `Alt + F8` から `InitializeCritiqueWorkbook` を実行する。設定シートと実行ボタンが作成される。ブックを保存する。
6. Windowsの「ユーザー環境変数」に `OPENAI_API_KEY` を追加し、OpenAI APIキーを設定する。Excelをすべて閉じて起動し直す。キーをセルやVBAコードに書かない。

モックだけを使用する場合は手順6は不要です。既存ブックを更新する場合は先にブックのバックアップを取り、VBEで旧版の同名モジュールを削除してから4つの新版をインポートしてください。同名のモジュールを重複して取り込まないでください。その後 `InitializeCritiqueWorkbook` を再実行すると、既存シートのモデル名などを保持して、モデル候補とモック設定欄を追加します。

信頼できるこのブックに対してのみマクロを許可してください。組織のマクロ制限がある場合は、その運用に従ってください。日本語版以外のWindowsではVBEのコードページ設定に注意してください。

## Excel版の使用方法

設定シート「小説批評」で次の項目を設定します。

| セル | 項目 | 初期値 |
| --- | --- | --- |
| B2 | AIモデル（候補選択・直接入力可） | `gpt-4.1-mini` |
| B3 | 入力の文字コード | `utf-8`（`shift_jis`も選択可） |
| B4 | 各批評・総評の最大出力トークン | `4000` |
| B14 | 実行モード（本番／モック） | 本番 |
| B15 | モック途中データから再開（はい／いいえ） | いいえ |
| B16 | 指定回の完了後にモック停止（1～6） | 空欄＝停止なし |
| B17 | 指定回でモックエラー発生（1～6） | 空欄＝エラーなし |
| B23 | 入力文字数の下限 | 空欄＝制限なし |
| B24 | 入力文字数の上限 | 空欄＝制限なし |

B2のプルダウン候補はPython版と同じ `gpt-4.1-mini`、`gpt-4.1`、`gpt-4.1-nano`、`gpt-5`、`gpt-5-mini`、`gpt-5-nano` です。候補以外も直接入力できます。選択したモデルを5人の評価と6回目の総評のすべてに使用します。モデルの利用可否はAPIプロジェクトの権限に依存します。一覧の表示時には通信しません。

### Excel版の文字数閾値

B23・B24に0～2147483647の整数を設定できます。空欄はその側の制限なしで、片側だけでも指定できます。下限が上限より大きい場合はエラーです。下限・上限と同じ文字数は評価対象です。

Python版と同じく空白・改行を含むUnicodeコードポイント数で数えます。先頭のUTF-8 BOMは読み込み時に除去し、CRLF・CRはLFに統一して1文字と数えます。絵文字などのUTF-16サロゲートペアは1文字です。結合文字の組合せは見た目の文字数と一致しない場合があります。本文そのものは切り詰めません。

下限未満ならファイル名と `閾値の下限を下回っているため評価無し`、上限超過ならファイル名と `閾値の上限を上回っているので評価無し` の2行だけを、選択した保存先へ出力します。APIキー確認・送信確認・評価処理に入る前に判定するため、本番モードでも範囲外ならAPIキーは不要で通信・課金はありません。モックの場合のみ末尾にテスト専用マーカーを追加します。閾値による評価無しでは、モックの途中データは作成・読み込みしません。

空ファイルも下限が1以上なら「下限未満」を保存します。閾値に該当しない空ファイルは従来どおりエラーです。既存ファイルは上書きしません。モデル・文字コード・出力トークンなど他の設定には正しい値を指定してください。

既存ブックの更新は `NovelCritique` と `CritiqueTests` を新版に差し替え、`InitializeCritiqueWorkbook` を再実行してください。B23・B24の欄が追加され、既存の設定値は保持されます。

本番モードでは「小説を評価する」を押し、入力ファイルと結果の保存先を選びます。送信確認後に本文をOpenAI APIに送信します。API利用料金が発生し、ChatGPTの契約とは別にAPIの利用設定が必要です。モデルは自身のAPIプロジェクトで利用できるものを指定してください。

APIキーは実行時に環境変数から読み、ファイルに保存しません。API送信先は `https://api.openai.com/v1/responses` です。`store: false` を指定しますが、OpenAI側のデータ取扱いについては利用するAPIの規約・設定を確認してください。

処理は同期実行のため、通信中はExcelの操作が待機状態になります。ステータスバーに現在の審査員を表示します。失敗した場合は結果ファイルを作成せず、その時点で停止します。本番では自動再試行・途中再開は行いません。再実行時には最初から評価するため、成功済みの送信にも再度料金が発生します。

### Excel版のモックテスト

モックではAPIキーは不要で、WinHTTPの通信処理に入らず、ネットワーク通信・API課金は発生しません。本番と同じ順番で5人のダミー批評と、批評だけを受け取る6回目のダミー総評を生成します。

1. B14を「モック」にし、B15を「いいえ」、B16・B17を空欄にします。
2. 「小説を評価する」で入力と保存先を選択すると、6回分を完了し、ファイルを保存します。自動保存名は `入力名_MOCK_批評.txt` です。
3. 各批評・総評には `【モックテスト専用・本番審査ではありません】` と表示します。任意のファイル名でも表示は残ります。
4. 途中停止は、別の保存先を使ってB16を `3` にして実行します。3人分の完了後に停止し、完成結果ファイルはまだ作りません。
5. B15を「はい」、B16を空欄にし、同じ入力と同じ保存先を選んで実行すると、成功済みの結果を再利用して残りを実行します。
6. エラーを試すにはB17を `1`～`6` に設定します。再開するときはB17を空欄に戻してB15を「はい」にします。6回目の総評でのエラー・停止にも対応します。

途中データは `保存先.txt.excel-mock-state.json` に保存します。入力ファイル名と本文のSHA-256、およびダミー結果だけを保存し、小説本文とAPIキーは記録しません。SHA-256はVBA内で計算し、Windowsの暗号APIは呼びません。同名の入力でも本文が変わった場合、不正・不足した途中データでは再開しません。Python版の途中ファイルとは形式が異なり、相互に再開することはできません。

旧版で「モック用のSHA-256計算に失敗しました」と表示された場合は、新しいZIP内の `MockReview.bas` に差し替えてください。SHA-256用のWindows API呼び出しを廃止しています。VBEで古い `MockReview` モジュールを削除して新版をインポートし、「デバッグ → VBAProjectのコンパイル」を実行してください。計算に失敗した場合は、処理段階と元のエラー番号を表示するようにしています。

完成結果と途中データは完了後も残ります。新しく試す場合は別の保存先を指定するか、前のモック結果と途中データを削除してください。既存の完成結果は上書きしません。完成ファイルの保存に失敗したときも、保存先の問題を解消して、同じ保存先・途中データから再開できます。

本番に戻すときはB14を「本番」にします。本番ではB15～B17を使わず、モックの途中データも読みません。APIキーと本番送信確認は従来どおり必要です。

長編の分割処理はありません。小説全文と指示がモデルの入力上限に収まる必要があります。出力が上限で打ち切られた場合も未完了として停止します。既存の出力ファイルは上書きしません。入力ファイルも変更しません。

## Excel版の検証

Windows Excelで `RunCritiqueSelfTests` を実行すると、通信を行わず、JSONの日本語・Unicode・特殊文字の処理、不正なJSONの拒否、Responses API形式のテキスト抽出、未完了・空応答・拒否応答の検出を17項目確認します。

`RunExcelMockSelfTests` はExcelモック用の追加テストです。SHA-256の既知値、3回目・6回目での停止、全6段階それぞれでのエラーと再開、本文変更の拒否、出力レイアウト、日本語ファイル保存、既存ファイル保護をローカルの一時フォルダーで検証します。通信は行いません。このVBAテストはクラウドでは未実行です。

`RunExcelThresholdSelfTests` は閾値判定の19項目を確認します。下限未満・上限超過の出力文、境界値、空欄、0、空ファイル、日本語・絵文字・改行の文字数、不正値を通信なしでテストします。このVBAテストもクラウドでは未実行です。

その後、短い小説のテキストファイルで実際の評価を1回実行し、次を確認してください。この操作にはAPI料金が発生します。

- 先頭に入力ファイル名があり、審査員１～５、総評が順に出力される。
- 日本語の批評文が保存され、文字化けしない。
- 入力ファイルが変更されていない。
- 既存の出力名を選ぶと、API送信前に停止する。

**このクラウド環境で確認済みなのは配布ファイルの生成・文字コードの往復変換・ZIP内容の整合性です。Windows Excelでのコンパイル、上記VBAテスト、実API通信は未実行です。**

## 開発

`excel/*.bas` をUTF-8で編集し、Python 3で `python3 tools/package_excel.py` を実行すると、CP932・CRLFの配布ZIPを再生成できます。配布処理の検証は `python3 -m unittest discover -s tests -v` です。Pythonは配布物を作る開発者だけが必要です。

詳細な動作仕様は [docs/specification.md](docs/specification.md) を参照してください。

## Python版

Python 3.10以上で [novel_critique.py](novel_critique.py) を実行します。標準ライブラリのみで動作するため、`pip install` は不要です。Excel版と同じ評価方針・出力レイアウトです。Excelとの接続は不要です。

Windowsのユーザー環境変数 `OPENAI_API_KEY` にAPIキーを設定し、ターミナルを開き直します。キーをソースファイルに書いたり、コマンドの引数に渡したりする必要はありません。macOS・Linuxでも同名の環境変数を使用します。

ファイルのあるフォルダーで実行します（Windowsの例）。

```powershell
py novel_critique.py "小説.txt" -o "小説_批評.txt"
```

`-o` を省略すると、入力と同じフォルダーに `入力名_批評.txt` を保存します。実行すると小説全文をOpenAI APIに送信し、合計6回のAPI料金が発生します。各処理の進行状況はターミナルに表示します。

入力は標準でUTF-8（BOMの有無どちらも対応）です。Windowsの従来の日本語テキストなら `--encoding cp932` を指定します。

```powershell
py novel_critique.py "小説.txt" --encoding cp932 --model gpt-4.1-mini --max-output-tokens 4000
```

macOS・Linuxでは `py` の代わりに `python3` を使用してください。モデルは自身のAPIプロジェクトで利用できるResponses API対応モデルを指定します。通信タイムアウトは1回180秒、`--timeout` で変更できます。

本文を自動分割せず、そのまま各審査員に渡します。長編ではモデルの入力上限に注意してください。入力ファイルの変更、既存出力の上書き、自動再試行は行いません。途中で失敗した場合は結果ファイルを作成しません。再実行は最初からになり、送信済みの処理には料金が発生する場合があります。APIキーやAPIの生のエラー本文はログに出しません。

出力はUTF-8（BOM付き）、改行はCRLFです。完成したファイルだけを保存先に公開するため、出力先はハードリンクに対応したファイルシステム（通常のNTFS、APFS、ext4など）を使用してください。一部のクラウド同期先・ネットワーク共有などで保存できない場合は、ローカルのフォルダーを指定してください。

Python版の検証は次のコマンドで実行できます。OpenAIには接続せず、料金は発生しません。

```powershell
py -m unittest discover -s tests -v
```

この環境では全36テスト（Pythonの評価処理16件、画面のバックグラウンド処理7件、モックモード11件、Excel配布処理2件）が成功しました。ローカルの模擬HTTP APIを使用した本番経路の回帰テストに加え、モックでの通信禁止、6段階の実行、途中停止・再開、エラー後の再開、保存失敗などを検証しています。実際のOpenAI APIへの通信は未実施です。

## Python版の画面

## AI文学賞 受賞作品決定ツール

既存の批評結果ファイルを比較して、1作品を第1位として選ぶ独立GUIツールです。小説本文は読み込まず、各 `.txt` の批評結果だけを比較します。元ファイルの1行目を作品タイトルとして扱い、「審査員１」～「審査員５」と「総評」を含む形式に対応します。

Windowsでは、ZIPを展開して `start_award_decider_silent.vbs` をダブルクリックすると、コマンド画面を表示せずに起動します。内部では `pyw`、なければ `pythonw` を使用します。Python 3.10以上が必要です。追加ライブラリはなく、`requirements-award.txt` にも外部依存なしと記載しています。起動できない場合や詳細なエラーを確認する場合だけ、診断用の `start_award_decider.bat` を実行してください。BATはコマンド画面を表示します。

画面で批評結果フォルダを選択すると、`.txt` の一覧、読み込み件数、合計文字数、推定入力トークン数が表示されます。「出力先フォルダ」の「フォルダ選択…」から結果を保存するフォルダを選べます。実行時に `受賞作品決定結果_YYYYMMDD_HHMMSS.txt` を自動生成し、同名がある場合は `_2`、`_3` のように別名で保存します。入力フォルダと同じ場所も選択できます。`受賞作品決定結果_` で始まる過去の結果は、次回の比較対象から自動的に除外します。2作品以上では全ファイルを1回の比較リクエストに渡し、必ず1作品を第1位に選びます。1作品ならAPIを呼ばず、その作品を第1位として扱います。0作品なら「対象ファイルがありません」と表示します。

入力がモデルの入力上限を超える可能性がある場合は、実行を止めます。入力の削除・切り捨て・要約や、一部作品だけの比較は行いません。推定値は文字数÷4の保守的な目安で、100,000トークンを明らかに超える場合に停止します。モデル固有の上限を取得できないため、上限未満でもAPI側で拒否される可能性があります。

APIキーは画面で伏せ字入力し、保存・ログ出力しません。起動時に環境変数のAPIキーがあれば、OpenAIのModels APIからそのキーで参照できるモデル一覧を自動取得します。画面でキーを入力した場合は「モデル一覧を取得」を押すか、APIキー欄でEnterを押してください。固定候補は持たず、取得した一覧をプルダウンへ反映します。取得失敗時はプルダウンに `モデルの取得に失敗しました。APIキーの設定とインターネット接続を行ってください。` と表示し、その状態では本番選考を開始しません。Models APIの一覧には文章生成以外のモデルが含まれる可能性があり、選択モデルがResponses APIで使えない場合は実行時にAPIエラーになります。選択したモデルを全作品の比較に使用し、結果ファイルの「使用モデル」に記録します。選考結果はUTF-8 BOM付きテキストで、指定された見出し、受賞作品、理由、特に優れている点、他作品との比較、留意点、実行情報を保存します。正常完了したResponses APIの `usage` から入力・出力・合計トークン数を取得し、返された場合はキャッシュ済み入力と推論トークンの内訳も記録します。利用情報が応答にない場合は「取得不可」、1作品だけまたはモックでAPIを呼ばない場合は「API未使用（0）」と記録します。

比較時は各作品に `C001`、`C002` の候補IDを付け、AIには第1位の候補IDだけを返させます。作品タイトルと批評ファイル名はAIの文字列を信用せず、アプリが候補IDから元の一覧へ照合して出力します。これにより、1行目の元小説ファイル名と批評ファイル名が似ている場合の取り違えを防ぎます。

「モックテスト（通信・課金なし）」を選ぶと、APIキーなしで一覧表示、全作品比較の流れ、結果表示、保存を確認できます。ダミー結果には `【モックテスト専用・実際の受賞判定ではありません】` と明記します。モックは入力順の先頭作品を仮の第1位にするだけで、文学的な優劣を判定しません。

この独立ツールの自動テストは次のコマンドで実行します。

```powershell
py -m unittest tests.test_award_decider -v
```

既存ツールを含めた全テストは `py -m unittest discover -s tests -v` です。GUIの実際のフォルダダイアログ操作はディスプレイのない環境では実行できないため、コア処理とモック保存をテストしています。

アプリ全体の右端に縦スクロールバーがあります。小さい画面でも、スクロールして下部の実行ボタンや結果欄に移動できます。Windowsのマウスホイールにも対応しています。結果欄の上では結果の文章をスクロールします。ウィンドウの高さは起動時に画面サイズに合わせ、さらに小さく変更することもできます。

`novel_critique.py`、`novel_critique_gui.py`、`mock_review.py` を同じフォルダーに置き、次のコマンドで起動します。配布ZIPには必要なファイルを同梱しています。

```powershell
py novel_critique_gui.py
```

Windowsでは同じフォルダーの `start_gui.bat` をダブルクリックしても起動できます。macOS・Linuxでは `python3 novel_critique_gui.py` を実行してください。画面はTkinterを使用します。Windowsの公式PythonインストーラーではTcl/Tkの機能を有効にしてください。LinuxなどでTkinterがない場合はOSの `python3-tk` パッケージが必要です。`python -m tkinter` でウィンドウが開くか確認できます。

配布ZIPは展開後、`start_gui_silent.vbs` をダブルクリックすると、コマンド画面を表示せずに起動できます。内部ではWindowsの `pyw` ランチャーを優先し、なければ `pythonw` を使用します。Python 3またはTkinterが見つからない場合はダイアログで案内します。外部ライブラリはなく、`pip install` は不要です。ZIP内のファイルは同じフォルダに置いたまま使用してください。起動できない場合や詳細なエラーを確認する場合だけ、診断用の `start_gui.bat` を実行してください。BATはコマンド画面を表示します。

1. 「小説ファイル」の「参照…」からテキストを選びます。保存先は自動で `入力名_批評.txt` に設定され、別の場所にも変更できます。
2. APIキーを入力します。`OPENAI_API_KEY` が設定済みなら自動で読み込みます。キーは伏せ字で表示し、設定ファイルには保存しません。
3. 起動時に環境変数のAPIキーがあれば、OpenAIのModels APIからモデル一覧を自動取得します。画面でAPIキーを入力した場合は、入力欄から移動するかEnterを押すか、「モデル一覧を取得」を押してください。固定候補は使用しません。取得したプルダウンから選んだモデルを5人の評価と総評のすべてに使用します。
   必要に応じて入力文字コード、最大出力トークン、通信タイムアウト、入力文字数の下限・上限を変更します。
4. 「評価を開始する」を押します。本文をOpenAI APIへ送信し、6回分のAPI料金が発生します。
5. 進捗バーと審査員の状態を確認します。完了すると結果ファイルを保存し、画面下部に同じ文章を表示します。

評価中も画面は応答しますが、二重実行や設定変更はできません。本番モードには途中停止・再開機能はありません。通常の終了ボタンを押した場合は完了まで待つよう案内します。タスクマネージャーなどで強制終了すると、送信済みのAPI料金が発生しても結果が保存されない場合があります。既存ファイルは上書きしません。モック専用の停止・再開については下記を参照してください。

クラウド環境では画面のバックグラウンド処理をテスト済みです。ディスプレイがないため、実際のウィンドウ表示・ボタン操作は未検証です。

モデル一覧の取得に失敗した場合、プルダウンに `モデルの取得に失敗しました。APIキーの設定とインターネット接続を行ってください。` と表示し、その状態では本番評価を開始しません。Models APIの一覧には文章生成以外のモデルも含まれる可能性があり、選択モデルがResponses APIで利用できない場合は実行時にAPIエラーになります。モデルによって料金・入力上限が異なり、推論モデルでは内部の推論にも出力トークン枠を使うため、未完了になる場合は最大出力トークンを調整してください。モックモードはモデルを取得できなくても実行でき、固定のダミー結果を返します。

### 入力文字数の閾値（Python版）

画面の「入力文字数の下限」「入力文字数の上限」に0以上の整数を入力できます。空欄はその側の制限なしです。下限だけ・上限だけの設定も可能です。下限が上限より大きい設定はエラーになります。下限・上限と同じ文字数なら評価します。

文字数は読み込んだテキストのUnicodeコードポイント数です。空白・改行も含みます。UTF-8の先頭BOMは除き、CRLFなどの改行はLFに統一して1文字として数えます。見た目の1文字と一致しない結合文字・絵文字の組合せもあります。本文は切り詰めません。

下限未満の場合は、APIを呼ばず、次の2行だけを保存・表示します。

```text
小説.txt
閾値の下限を下回っているため評価無し
```

上限超過の場合もAPIを呼ばず、次の2行だけを保存・表示します。

```text
小説.txt
閾値の上限を上回っているので評価無し
```

この場合はAPIキーが未設定でも出力でき、API料金は発生しません。既存の出力ファイルは上書きしません。空ファイルも下限を1以上に設定していれば「下限未満」の出力になります。閾値に該当しない空ファイルは従来どおり入力エラーです。

コマンドラインでも指定できます。

```powershell
py novel_critique.py "小説.txt" -o "批評.txt" --min-chars 1000 --max-chars 20000
```

省略した側は制限なしです。範囲外の出力は正常終了（終了コード0）として扱います。Excel版でもB23・B24で同じ閾値判定を利用できます。

## モックテストモード（Python版）

**モックではOpenAI APIを一切呼ばず、ネットワーク通信・API課金は発生しません。APIキーも不要です。** モック専用処理から固定のダミー文章を返し、本番と同じ5人の独立評価→批評だけを使う6回目の総評→テキスト保存の流れを通します。本番のAPIクライアントは生成しません。

モックは明示的に有効にしたときだけ動きます。指定なしは従来どおり本番です。本番の評価方針・リクエスト・ファイル形式・失敗時の挙動は変えていません。Excel版でも上記「Excel版のモックテスト」の設定で同等の機能を利用できます。

### 画面で試す

1. `start_gui.bat` または `py novel_critique_gui.py` で起動します。
2. 「モックテスト（通信・課金なし）」にチェックを入れ、短い小説ファイルを選択します。自動保存名は `入力名_MOCK_批評.txt` です。
3. そのまま「評価を開始する」で6段階を実行し、結果の表示・保存を確認できます。
4. 途中停止を試すには「停止する回（完了後）」で、例えば `3` を選んで実行します。3人分を保存した時点で停止し、完成結果ファイルはまだ作りません。
5. 同じ入力・保存先で「モック途中データから再開」にチェックを入れて実行します。保存済みの評価を再利用し、残りを実行して結果を保存します。停止位置は空欄に戻して構いません。
6. エラーを試すには「エラーを起こす回」を `1`～`6` に設定します。エラー後はこの欄を空欄に戻し、「再開」にチェックを入れて実行します。

モック結果には各批評・総評に `【モックテスト専用・本番審査ではありません】` を表示します。任意の保存名を指定した場合もこの表示は残ります。閾値による評価無しの場合もモック表示を追記します。モックの文章は内容の良し悪しを評価するものではありません。

### コマンドから試す

通常完了（APIキーなしで実行できます）。

```powershell
py novel_critique.py "小説.txt" --mock
```

3回目の完了後に停止し、次のコマンドで再開します。

```powershell
py novel_critique.py "小説.txt" --mock -o "停止テスト.txt" --mock-stop-after 3
py novel_critique.py "小説.txt" --mock -o "停止テスト.txt" --mock-resume
```

4回目にテスト用エラーを起こし、成功済みの結果から再開します。

```powershell
py novel_critique.py "小説.txt" --mock -o "エラーテスト.txt" --mock-fail-at 4
py novel_critique.py "小説.txt" --mock -o "エラーテスト.txt" --mock-resume
```

途中データは、保存先の末尾に `.mock-state.json` を付けたファイルです。モック識別子、入力のハッシュ、成功済みのダミー結果だけを保存し、小説本文やAPIキーは保存しません。再開時には同じ入力ファイル名・本文と途中データが必要です。本文が変更された場合、途中データが不正な場合は再開を拒否します。停止・エラー発生回の指定は実行時だけの設定で、途中データには保存しません。

完了後も途中データを残します。新しいテストを最初から行う場合は別の保存名を指定するか、前のモック結果とその途中データを削除してください。既存結果を上書きすることはありません。保存失敗の場合も、保存先の問題を解消してから同じ途中データで再開できます。6回目完了後の停止にも対応します。

終了コードは正常完了・閾値による評価無しが `0`、テスト用エラー・保存失敗などが `1`、設定不正が `2`、指定位置でのモック停止が `3` です。`--mock-*` だけを指定して本番を誤実行することはできません。

### 自動テスト


モックのテストではソケット生成、通信クライアント生成を例外に差し替えて、通信経路に入ると失敗するようにしています。全6段階の完了、各段階でのエラー、停止・再開、結果の識別、既存ファイル保護、保存失敗からの再開を確認します。既存の本番経路のテストも引き続き実行します。画面の実表示・手操作はこのクラウド環境では未確認です。

## Python版でHTTP 404が出た場合

画面のモデル候補は利用権限を確認した一覧ではありません。`gpt-4.1-nano` を選んで404になった場合も、HTTPステータスだけでは原因を断定できません。

新版はAPIから `model_not_found` が返った場合に、そのコードと、指定モデルが存在しないかAPIキーのプロジェクトで利用できない旨を表示します。それ以外の404では原因未確定として、プロジェクト設定・接続環境の確認を案内します。APIの生のエラー本文やAPIキーは表示しません。

[OpenAI Platform](https://platform.openai.com/) でAPIキーの所属プロジェクトとモデルへのアクセスを確認し、そのプロジェクトで使用可能なResponses API対応モデルを選択してください。候補に載っていることは、そのキーで使えることを保証しません。モデル名を変更するときは入力欄の余分な文字も確認してください。別モデルへの自動切り替え・自動再試行は行いません。

更新はZIPを展開し、`novel_critique.py` を新版に差し替えてアプリを再起動してください。この改善は原因の表示を詳しくするもので、API側の利用権限を変更するものではありません。
